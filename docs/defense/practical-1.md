# Практична 1 — підготовка до захисту

## Чим відрізняються `let` і `var`? Як незмінність пов'язана з типом значення?

- `let` — константа: після першого присвоєння змінна не може «вказувати» на інше значення.
  `var` — змінна: її можна перепризначити.
- Для **типів-значень** (`struct`, `enum`, масиви) `let` означає *повну* незмінність:
  `let profile = try QuitProfile(...)` — не можна змінити жодне поле, навіть `var`-поле
  структури (`profile.cigarettesPerDay = 5` — помилка компіляції).
- Для **типів-посилань** (`class`) `let` фіксує лише *посилання*: `let journal = CravingJournal()` —
  не можна зробити `journal = інший`, але можна викликати `journal.add(...)`, бо змінюється
  вміст об'єкта, а не саме посилання.
- Приклад у проєкті: `var profileCopy = profile` (`ConsoleScenario`) — для зміни копії
  структури змінна має бути `var`.

## Чим відрізняються структура та клас? Семантика значення та посилання

| | `struct` | `class` |
|---|---|---|
| Семантика | значення — при присвоєнні **копіюється** | посилання — копіюється лише **посилання** на той самий об'єкт |
| Успадкування | немає | є |
| Ідентичність (`===`) | немає | є |
| Memberwise init | автоматично | ні |

- `QuitProfile`, `HealthMilestone`, `CravingEvent` — `struct`: це прості дані. Копія профілю
  незалежна від оригіналу, що безпечно передавати між екранами й потоками.
- `CravingJournal` — `class`: це єдиний спільний журнал зі зміною стану. Усі, хто тримає
  посилання, бачать однакові дані (`journal` і `sameJournal` у `ConsoleScenario`).

## Для чого потрібні протоколи та переліки (`enum`)?

- **Протокол** — контракт «що вміє тип» без реалізації. `ProgressCalculating` дозволяє
  підставити іншу реалізацію (у тестах — фіксовану) без зміни коду, що її використовує.
- **Enum** — скінченна множина взаємовиключних значень із власною поведінкою:
  `Currency` (валюти + символ), `CravingTrigger` (тригери + іконка), `ProfileValidationError`
  (помилки з поясненням). Компілятор змушує обробити всі випадки в `switch`.

## Що таке Optional і як безпечно працювати з відсутнім значенням?

`Optional<T>` (`T?`) — це `enum` із двома станами: `.some(значення)` або `.none` (`nil`).
Безпечні способи:

- `if let next = HealthMilestone.catalog.first(where: …) { … } else { … }` (`ConsoleScenario`)
- `guard let … else { return }`
- `??` (значення за замовчуванням), опціональний ланцюжок `a?.b`, `map`
- `try?` перетворює помилку на `nil` (`ConsoleScenario`: некоректний профіль → `nil`)

Force unwrap `!` небезпечний — при `nil` застосунок аварійно завершиться, тому в проєкті
не використовується.

## Чим відрізняються `commit`, `push`, `pull`? Для чого `.gitignore`?

- `git commit` — зафіксувати підготовлений (`git add`) стан у **локальній** історії.
- `git push` — відправити локальні коміти у віддалений репозиторій (незакомічені зміни не передаються).
- `git pull` — `fetch` (отримати віддалену історію) + `merge` (інтегрувати її в поточну гілку).
- `.gitignore` — перелік шаблонів файлів, які Git не відстежує: `xcuserdata`, `DerivedData`,
  `.DS_Store`, ключі/сертифікати. Не видаляє файли, що **вже** відстежуються.
